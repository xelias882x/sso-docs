Slide 01 · Conceito

O que é SSO?

Single Sign-On — Um único login corporativo para todos os sistemas

🔴 Sem SSO

  • Senha nova para cada sistema
  • Usuário lembra 5–10 senhas
  • TI gerencia contas duplicadas
  • Acesso não revogado ao demitir
  • Senhas fracas / reaproveitadas
  • Suporte: "esqueci minha senha"

🟢 Com SSO

  • Uma conta Microsoft para tudo
  • Login automático nos sistemas
  • TI gerencia no Azure AD
  • Demissão revoga tudo de uma vez
  • Senha forte do M365 (MFA)
  • Zero chamados de senha
Definição simples: O usuário faz login uma única vez com a conta da empresa (Microsoft 365) e o sistema confirma a identidade sem pedir nova senha.
🔑

Protocolo: OAuth 2.0 + PKCE

Padrão internacional adotado por Microsoft, Google, Apple. A senha nunca trafega no sistema — apenas tokens assinados.

🛡️

Quem garante a identidade?

A Microsoft. Seu sistema recebe confirmação criptográfica assinada pelo Azure Active Directory.

Slide 08 · Defense in Depth

Camadas de Segurança

Modelo de defesa em profundidade — múltiplas barreiras independentes

🔑 Camada 1 — Identidade
Azure AD (Microsoft Entra ID) · MFA obrigatório pelo M365 · Conta corporativa verificada
🍪 Camada 2 — Sessão
HMAC-SHA1 (itsdangerous) · HttpOnly · SameSite=Lax · Secure em HTTPS · Expiração 8h · Cleanup automático
📜 Camada 3 — Token JWT
Valida: exp (expiração) · aud (audiência) · iss (issuer/Microsoft) · nonce (replay) · tid (empresa autorizada)
🔄 Camada 4 — Protocolo
PKCE (code_verifier/challenge) · state CSRF · TTL 10min · Máx 200 estados simultâneos
🌐 Camada 5 — Headers HTTP
Content-Security-Policy · X-Frame-Options: DENY · X-Content-Type-Options: nosniff · Referrer-Policy
☁️ Camada 6 — Infra
HTTPS obrigatório · HSTS · Secret Manager GCP · Container não-root · /docs desabilitado
